#laravel #cheatsheet #medialens

Uitleg voor mezelf van wat ik gedaan heb bij bouwblok 4 van de MediaLens casus: de Educom LiteLLM-API koppelen, configuratie via `.env` en `config/services.php`, en artikelen van één gebeurtenis laten vergelijken.

## Wat is LiteLLM
LiteLLM is geen model zelf, maar een proxy. Ik praat tegen `https://ai.educom.nu`, die stuurt het door naar een model. Het protocol is hetzelfde als OpenAI: JSON met `model` en `messages`.

Voor het traineeship moet ik deze API gebruiken, niet OpenAI rechtstreeks. Swagger staat op dezelfde URL. De key autoriseer ik daar via het slotje.

Twee endpoints die ik nodig had:
- `GET /v1/models`: welke modellen mag mijn key gebruiken
- `POST /v1/chat/completions`: tekst laten genereren

`GET /models/{model_id}` is alleen info over één model. Daar vergelijk ik geen artikelen mee.

Mijn key mag één model: `Educom_Trainees_Smart_Router`. Die naam gaat later in de POST-body, niet in de URL.

Swagger stuurde de key als header `x-litellm-api-key`, niet als `Authorization: Bearer`. Die header gebruik ik ook in Laravel.

> [!warning] De API-key hoort in `.env`, nooit in git, README of een screenshot van de curl-regel. Swagger plakt de key zichtbaar in het curl-voorbeeld.

## Secrets in .env
Laravel leest geheimen uit `.env`. Dat is hetzelfde patroon als mijn databasewachtwoord.
```env
LITELLM_BASE_URL=https://ai.educom.nu
LITELLM_API_KEY=
LITELLM_MODEL=openrouter/deepseek/deepseek-v4-flash
LITELLM_THINKING_TYPE=
LITELLM_REASONING_EFFORT=
LITELLM_TEMPERATURE=
LITELLM_PRICE_INPUT=0.14
LITELLM_PRICE_OUTPUT=0.28
LITELLM_PRICE_CACHED=0.014
```

De drie `PRICE_`-regels staan bewust onder het model. Wissel ik van model, dan pas ik de tarieven op dezelfde plek aan. Die getallen zijn per 1 miljoen tokens, in dollars (OpenRouter). Zonder `/ 1_000_000` in de code zou 1 token even duur lijken als 1 miljoen.

`THINKING_TYPE`, `REASONING_EFFORT` en `TEMPERATURE` mogen leeg. De standaard staat in `config/services.php`, niet in de PHP-aanroep. Uitleg van wat die knoppen doen: notitie 5.

In `.env.example` staan dezelfde namen, zonder echte key. Iemand anders die het project clonet vult zelf zijn key in.

In Tinker checken of de waarden binnenkomen, zonder de key te printen:
```php
[env('LITELLM_BASE_URL'), env('LITELLM_MODEL'), filled(env('LITELLM_API_KEY'))]
```

`filled()` is Laravel-helper: `true` als de waarde niet leeg is.

## env() alleen in config, daarna config()
Laravel-conventie: `env()` gebruik ik alleen in bestanden onder `config/`. In de rest van de app gebruik ik `config()`. Als config ooit gecached wordt (`php artisan config:cache`), werkt `env()` buiten die bestanden niet meer betrouwbaar.

In `config/services.php` hoort third-party spul, naast Postmark en Slack:
```php
'litellm' => [
    'base_url' => env('LITELLM_BASE_URL'),
    'api_key' => env('LITELLM_API_KEY'),
    'model' => env('LITELLM_MODEL'),
    'price_input' => (float) env('LITELLM_PRICE_INPUT', 0),
    'price_output' => (float) env('LITELLM_PRICE_OUTPUT', 0),
    'price_cached' => (float) env('LITELLM_PRICE_CACHED', 0),
    'thinking_type' => env('LITELLM_THINKING_TYPE') ?: 'enabled',
    'reasoning_effort' => env('LITELLM_REASONING_EFFORT') ?: 'high',
    'temperature' => is_numeric(env('LITELLM_TEMPERATURE'))
        ? (float) env('LITELLM_TEMPERATURE')
        : 1,
],
```

`(float)` is nodig: `env()` geeft een string. Default `0` bij prijzen betekent: niet ingevuld, kosten komen op 0 uit.

`?:` pakt de standaard bij `null` én bij een lege string. `env('LITELLM_THINKING_TYPE', 'enabled')` doet dat niet: een regel `LITELLM_THINKING_TYPE=` in `.env` is een lege string, en dan wint die lege string van de tweede parameter.

Temperature is een float, en `0` is geldig. `?:` zou `0` ook als leeg zien. `is_numeric()` laat `0` en `0.3` door en valt bij leeg of onzin terug op `1`.

Ophalen:
```php
config('services.litellm.base_url');
config('services.litellm.api_key');
config('services.litellm.model');
config('services.litellm.price_input');
```

De punt-notatie volgt de keys in het array: `services` is het bestand, `litellm` is de key, daarna het veld.

## Eerste testhit met de HTTP client
Zelfde `Http::` als bij RSS ophalen, nu een POST met JSON-body.
```php
Illuminate\Support\Facades\Http::timeout(60)
    ->withHeaders(['x-litellm-api-key' => env('LITELLM_API_KEY')])
    ->post(rtrim(env('LITELLM_BASE_URL'), '/') . '/v1/chat/completions', [
        'model' => env('LITELLM_MODEL'),
        'messages' => [
            ['role' => 'user', 'content' => 'Zeg alleen: hallo'],
        ],
    ])
    ->json('choices.0.message.content');
```

- `timeout(60)`: een model mag langer duren dan een RSS-feed. Zonder timeout knalt Laravel eerder af.
- `rtrim(..., '/')` voorkomt een dubbele slash als de URL per ongeluk al op `/` eindigt.
- OpenAI-achtige API's zetten de tekst in `choices[0].message.content`. `json('choices.0.message.content')` is Laravel-dot-notatie in de JSON.

> [!note] Tinker voert elke regel apart uit. Een ketting die op de volgende regel met `->` begint, is een parse error (`unexpected T_OBJECT_OPERATOR`). Plak Tinker-code als één regel, of wikkel hem in `{ ... }`.

## Service-klasse LiteLlm
De testhit hoort niet in Tinker te blijven staan. Bouwblok 5 heeft later dezelfde aanroep nodig, dus een kleine herbruikbare class in plaats van alles in de vergelijker te stoppen.
```bash
php artisan make:class Services/LiteLlm
```

In bouwblok 3 had Laravel geen `make:service`. `make:class` bestaat wel en zet namespace en klassenaam goed.
```php
namespace App\Services;

use Illuminate\Support\Facades\Http;

class LiteLlm
{
    public function vraag(string $bericht): string
    {
        $response = Http::timeout(60)
            ->withHeaders([
                'x-litellm-api-key' => config('services.litellm.api_key'),
            ])
            ->post(rtrim(config('services.litellm.base_url'), '/') . '/v1/chat/completions', [
                'model' => config('services.litellm.model'),
                'messages' => [
                    ['role' => 'user', 'content' => $bericht],
                ],
            ]);

        if ($response->failed()) {
            return '';
        }

        return (string) $response->json('choices.0.message.content');
    }
}
```

`failed()` ken ik van het RSS-command: bij 4xx/5xx geen crash. Hier geef ik een lege string terug. De key komt uit `config()`, niet meer uit `env()`.

Test:
```php
(new App\Services\LiteLlm)->vraag('Zeg alleen: hallo')
```

> [!warning] Tinker laadt een gewijzigd PHP-bestand niet altijd live. Na een aanpassing: `exit` en opnieuw `php artisan tinker`.

## Artikelen van een gebeurtenis ophalen
`ArtikelVergelijker` heeft een andere verantwoordelijkheid dan `LiteLlm`: hij bouwt de input, LiteLlm stuurt hem op.
```bash
php artisan make:class Services/ArtikelVergelijker
```

Eerst alleen de tekst klaarzetten, nog geen AI. Zo kan ik de inhoud checken voordat ik tokens verbruik.
```php
public function artikelenTekst(Gebeurtenis $gebeurtenis): string
{
    $gebeurtenis->load('artikelen.bron');

    $regels = [];

    foreach ($gebeurtenis->artikelen as $artikel) {
        $tekst = trim(strip_tags((string) $artikel->volledige_tekst));

        $regels[] = "Bron: {$artikel->bron->naam}\n"
            . "Titel: {$artikel->titel}\n"
            . "Tekst: {$tekst}";
    }

    return implode("\n\n", $regels);
}
```

`$gebeurtenis->artikelen` is de `hasMany`-relatie uit bouwblok 1. `$artikel->bron` is `belongsTo`.

`load('artikelen.bron')` is eager loading: artikelen én hun bron in één keer, in plaats van een extra query per artikel (N+1). De punt betekent: laad van elk artikel ook de bron.

`strip_tags` haalt HTML uit de RSS-omschrijving, net als in de matcher.

> [!tip] Status 200 of "geen foutmelding" zegt niks over de groep. Ik lees of er meerdere bronnen in staan, en of alle titels over hetzelfde nieuwsfeit gaan.

## Groepen moeten schoon zijn
De vergelijker is zo goed als de groepen. Groep 4 mengde Christa Pike (executie Tennessee) met een dreigement bij het Texas Capitol. Dat is de ketting-matching uit bouwblok 3: de eerste kandidaat die de drempel haalt wint.

## De vergelijkingsprompt
De casus vraagt om taalgebruik, benadrukte onderwerpen en behandelde actoren. Nog geen neutrale samenvatting, dat is bouwblok 5.
```php
public function vergelijk(Gebeurtenis $gebeurtenis): string
{
    $artikelen = $this->artikelenTekst($gebeurtenis);

    $prompt = "Hieronder staan nieuwsartikelen over dezelfde gebeurtenis, uit bronnen met verschillende politieke oriëntatie.\n\n"
        . "Vergelijk de artikelen. Benoem:\n"
        . "- taalgebruik (neutraal, emotioneel, beladen woorden)\n"
        . "- welke onderwerpen extra worden benadrukt\n"
        . "- welke actoren (personen, instanties) worden genoemd of weggelaten\n\n"
        . "Artikelen:\n\n"
        . $artikelen;

    return (new LiteLlm)->vraag($prompt);
}
```

`LiteLlm` zit in dezelfde namespace `App\Services`. Een `use` bovenaan mag, het is niet verplicht.

Test met een schone groep:
```php
(new App\Services\ArtikelVergelijker)->vergelijk(App\Models\Gebeurtenis::find(5))
```

Dit kan 10 tot 30 seconden duren. Ik check of de AI per bron taal, nadruk en actoren uit elkaar haalt. Alleen "er komt tekst terug" is niet genoeg.

## Oriëntatie niet meegeven
Eerst stuurde ik `({$artikel->bron->orientatie})` mee. De output nam die labels over: Hill werd "neutraal" omdat het erbij stond, niet per se omdat de tekst dat liet zien.

De README waarschuwt al: de AI kan zelf vooringenomen zijn. Labels als `neutral` / `left-center` / `right` in de prompt zijn een extra duwtje. Die haal ik uit de artikeltekst. De oriëntatie blijft in de database, voor later, alleen de AI krijgt hem niet te zien.

In de prompt staat nog de zin "uit bronnen met verschillende politieke oriëntatie". Dat is geen label per artikel, maar het stuurt wel richting politiek. Kan ik later strakker maken.

## Waarom ik het zo heb aangepakt
LiteLLM spreekt OpenAI-formaat, dus ik hoef geen extra PHP-package. De HTTP-client kende ik al van RSS. Config via `services.php` is de Laravel-plek voor keys van buitenaf.

Twee classes: `LiteLlm` kent alleen "stuur een bericht, krijg tekst terug". `ArtikelVergelijker` kent gebeurtenissen, relaties en de prompt. Bouwblok 5 hergebruikt `vraag()` met een system-bericht, JSON-schema en optioneel een `gebeurtenis_id` voor de log. Prijzen en usage-logging horen in `LiteLlm`, niet in de vergelijker. Dat staat in notitie 5.

## Beperkingen om te onthouden
- Input is nog steeds de RSS-omschrijving, geen volledige artikeltekst.
- Vuile of gemengde groepen maken de vergelijking onbruikbaar, ook als de prompt goed is.
- `failed()` geeft een lege string, geen duidelijke foutmelding. Bij debuggen de `status()` erbij halen.
- `vergelijk()` staat in de huidige code uitgecommentarieerd. De draaiende aanroep is `samenvat()`, notitie 5.
- Het model komt uit `LITELLM_MODEL`. Nu `openrouter/deepseek/deepseek-v4-flash`, niet meer `Educom_Trainees_Smart_Router`. Output kan per run verschillen. Notitie 5.
- Oriëntatie zit nog in de promptzin van `vergelijk()`, niet meer per artikel. Die methode draait niet meer.
- `samenvat()` (notitie 5) vraagt later wél om schrijfwijze in overeenstemming/verschil, nog steeds zonder MBFC-label per artikel. Die keuze blijft: anders nabauwt het model `neutral` omdat het erbij stond.
