#laravel #cheatsheet #medialens

Uitleg voor mezelf van wat ik gedaan heb bij bouwblok 9 van de MediaLens casus: Links, Midden en Rechts als drie kolommen, ook als een bakje leeg is, plus dezelfde telling op het overzicht.

## Lege bakjes bestaan
`groupBy` maakt alleen een sleutel als er een artikel in zit. Geen artikel met `neutral` betekent: de sleutel `Midden` zit niet in de Collection. Een kolom voor Midden kan dan niet, en `$artikelenPerOrientatie['Midden']` zou niks zijn.

Na de `groupBy`, vóór `$volgorde` en `sortBy`:

```php
foreach (['Links', 'Midden', 'Rechts'] as $naam) {
    $artikelenPerOrientatie->put(
        $naam,
        $artikelenPerOrientatie->get($naam, collect())
    );
}
```

`get($naam, collect())` geeft de artikelen als het bakje er is, anders een lege Collection. `put` schrijft die onder `Links`, `Midden` of `Rechts`. `sortBy` daarna zet ze weer in die volgorde. Een onbekende `orientatie` blijft staan en zakt nog steeds naar onderen via `?? 4`.

In de view is een lege Collection geen `null`. `@foreach` erover crasht niet, hij print alleen niks. Zonder tekst zie je dan alleen een kop.

```blade
@if ($artikelen->isEmpty())
    <p class="mt-2 text-sm text-gray-600">Geen artikelen in dit bakje.</p>
@else
    <ul>
        {{-- artikelen, zoals in bouwblok 7 en 8 --}}
    </ul>
@endif
```

`isEmpty()` is een Collection-methode.

Check: `/gebeurtenissen/130` heeft Links en Rechts, geen Midden. Drie koppen, onder Midden de zin, geen fout. `/gebeurtenissen/207` heeft alleen Links. Midden en Rechts tonen allebei de zin.

## Drie kolommen
De bakjes stonden onder elkaar. Een `grid` legt de `<section>`s in een raster. Elk bakje is één kind van de grid.

```blade
<div class="mt-4 grid grid-cols-1 gap-6 md:grid-cols-3">
    @foreach ($artikelenPerOrientatie as $bakje => $artikelen)
        <section>
            <h3 class="text-lg font-semibold">{{ $bakje }}</h3>
            ...
        </section>
    @endforeach
</div>
```

`grid-cols-1` is één kolom: onder elkaar. `md:grid-cols-3` geldt vanaf 768px en maakt drie kolommen. `gap-6` is de ruimte ertussen. De titel, de bronnaam, het MBFC-label en de link per artikel blijven. De kolommen zitten in de bestaande `max-w-3xl` van de layout, dus op een breed scherm zijn ze smal en wrappen de titels.

`npm run dev` moet aanstaan. Een nieuwe Tailwind-class komt anders niet in de pagina.

Check: breed venster op `/gebeurtenissen/130` toont de drie bakjes naast elkaar, Midden met de zin. Venster smaller dan ongeveer 768px: weer onder elkaar, volgorde Links, Midden, Rechts.

## Footer bleef plakken aan de inhoud
Bij een korte pagina stopt de footer meteen onder de tekst. De rest van het venster is dezelfde witte achtergrond, dus de balk oogt alsof hij meegroeit. De footer-regel zelf is alleen de tekst plus `py-4`.

In `layouts/app.blade.php`:

```blade
<body class="flex min-h-screen flex-col bg-white text-gray-900">
    <header>...</header>
    <main class="mx-auto w-full max-w-3xl flex-1 px-4 py-6">
        @yield('content')
    </main>
    <footer>...</footer>
</body>
```

`flex flex-col` zet kop, inhoud en footer onder elkaar. `min-h-screen` is minstens de hoogte van het venster. Bij een lange pagina groeit de kolom mee. `flex-1` op `main` pakt de ruimte die over is, dus de lege hoogte zit in het midden. De footer blijft één regel onderaan. `w-full` houdt de kolom op een smal scherm even breed als het venster.

Check: `/gebeurtenissen/207` heeft de grijze regel onderaan het venster. Een lange pagina, zoals `/gebeurtenissen/130`, scrolt en de footer komt pas na de samenvatting.

## Telling op het overzicht
De casus noemt dit optioneel. Geen AI. Dezelfde drie bakjes als op de detailpagina.

`withCount('artikelen')` kende ik van bouwblok 6. Een array mag meerdere tellingen. `as links_count` is de naam van het extra getal op het model.

```php
->withCount([
    'artikelen',
    'artikelen as links_count' => function ($query) {
        $query->whereHas('bron', function ($bron) {
            $bron->whereIn('orientatie', ['left', 'left-center']);
        });
    },
    'artikelen as midden_count' => function ($query) {
        $query->whereHas('bron', function ($bron) {
            $bron->where('orientatie', 'neutral');
        });
    },
    'artikelen as rechts_count' => function ($query) {
        $query->whereHas('bron', function ($bron) {
            $bron->whereIn('orientatie', ['right-center', 'right']);
        });
    },
])
```

`'artikelen'` zonder meer blijft `artikelen_count`. Die haal ik nog op. In de lijst heb ik de regel met dat totaal weggehaald. Wat je ziet is de verdeling, niet het totaal.

`whereHas('bron', ...)` beperkt welke artikelen meetellen, via de `belongsTo` op `Artikel`. De oriëntaties zijn dezelfde map als `$bakjes` in `show()`. Dit zijn extra `COUNT`-subqueries in de lijst-query, geen query per rij.

In `index.blade.php`, onder het onderwerp:

```blade
<span class="block text-sm text-gray-600">
    Links {{ $gebeurtenis->links_count }},
    Midden {{ $gebeurtenis->midden_count }},
    Rechts {{ $gebeurtenis->rechts_count }}
</span>
```

`block` zet de telling op een eigen regel.

Check: de drie getallen bij het onderwerp van gebeurtenis 130 zijn gelijk aan het aantal artikelen in die kolommen. Midden is `0`. Gebeurtenis 207 toont Midden `0` en Rechts `0`.

## Waarom ik het zo heb aangepakt
Eerst de lege bakjes, nog onder elkaar, zodat een missende sleutel geen crash wordt. Daarna het raster. De footer tussendoor, omdat een korte testpagina de balk liet meegroeien in de witte ruimte. Als laatste de telling op het overzicht, met dezelfde indeling als de kolommen.

## Latere uitbreiding: verdelingsbalk en beeldkaarten (bouwblok 14)
De drie tellingen zijn nu ook een horizontale balk op de overzichtskaarten. De breedte van elk segment is de telling gedeeld door `artikelen_count`; de drie aantallen blijven daarnaast als tekst zichtbaar. De verdeling blijft gebaseerd op de bronoriëntatie per artikel, niet op een AI-oordeel over de tekst.

Op de detailpagina is elk artikel een beeldkaart binnen hetzelfde perspectiefbakje. De afbeelding verandert de indeling Links / Midden / Rechts niet. Zie `14. Visuele vormgeving en artikelafbeeldingen.md` voor de precieze velden en weergave.

## Beperkingen om te onthouden
- De drie kolommen zitten in `max-w-3xl`. Titels wrappen. Breder maken raakt ook de samenvatting, die nu bewust smal blijft.
- `md:` kijkt naar het venster (768px), niet naar de breedte van `main`.
- Een onbekende `orientatie` wordt een vierde cel in het raster, onder de drie vaste bakjes.
- `artikelen_count` zit nog in de query en niet in de HTML.
- De telling en de kolommen gebruiken dezelfde vijf labels. Een nieuwe oriëntatie in de seeder telt op het overzicht nergens mee tot beide plekken hem kennen.
