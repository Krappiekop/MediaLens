#laravel #cheatsheet #medialens

Uitleg voor mezelf van wat ik gedaan heb bij bouwblok 7 van de MediaLens casus: de detailpagina van één gebeurtenis, via route model binding, een `show`-view, samenvatting of lege staat, en artikelen in bakjes Links / Midden / Rechts.

## index vs show
`index` is de lijst (bouwblok 6). `show` is REST-conventie voor één record. Dezelfde `GebeurtenisController`, een tweede methode.

Eerste versie zonder Blade, om de keten te bewijzen: URL, route, binding.
```php
public function show(Gebeurtenis $gebeurtenis)
{
    return $gebeurtenis->onderwerp;
}
```

## Route model binding
In `routes/web.php`, onder de `index`-routes:
```php
Route::get('/gebeurtenissen/{gebeurtenis}', [GebeurtenisController::class, 'show']);
```

`{gebeurtenis}` is geen tekst in de URL, maar een plek voor het id. `/gebeurtenissen/5` vult dat met `5`. `/gebeurtenissen` zonder id blijft `index`. Die twee botsen niet.

**Laravel-concept:** de parameternaam `{gebeurtenis}` hoort bij het type-hint `Gebeurtenis $gebeurtenis`. Laravel doet zelf `findOrFail(5)`. Ik schrijf geen `find()` in de controller. Bestaat het id niet, dan 404. Zonder binding zou `find()` `null` geven en crasht `->onderwerp`.

`use App\Models\Gebeurtenis;` stond al bovenaan van `index()`.

Check: bestaand id toont het onderwerp uit phpMyAdmin. `http://127.0.0.1:8000/gebeurtenissen/99999` is 404. De lijst op `/gebeurtenissen` blijft werken.

## Blade-view show
Platte string vervangen door `view()`, hetzelfde als `index`.
```php
public function show(Gebeurtenis $gebeurtenis)
{
    return view('gebeurtenissen.show', [
        'gebeurtenis' => $gebeurtenis,
    ]);
}
```

`gebeurtenissen.show` is geen URL. De punt is de map: `resources/views/gebeurtenissen/show.blade.php`. Twee bestanden in dezelfde map: `index` en `show`.

Eerste inhoud, alleen het onderwerp. Route model binding heeft het model al, geen extra query.
```html
<!DOCTYPE html>
<html>
    <head>
        <title>{{ $gebeurtenis->onderwerp }}</title>
    </head>
    <body>
        <h1>{{ $gebeurtenis->onderwerp }}</h1>
    </body>
</html>
```

> [!warning] Bestand in `resources/views/show.blade.php` hoort bij `view('show')`. Dan: `View [gebeurtenissen.show] not found`, terwijl de controller klopt.

Check: dezelfde URL als net is nu HTML met het onderwerp als `<h1>` en als tabtitel. Onbestaand id blijft 404.

## Samenvatting: load() en lege staat
`with('samenvatting')` zit op een query vóór `get()`. Hier heeft Laravel het model al via het id. Dan `load()`: dezelfde eager load, op een bestaand object.

Queries horen in de controller. Anders trapt Blade `$gebeurtenis->samenvatting` lui af.
```php
$gebeurtenis->load('samenvatting');
```

`'samenvatting'` is de `hasOne` uit bouwblok 1. Daarna is `$gebeurtenis->samenvatting` het model of `null`. Dat kende ik van Tinker in bouwblok 5.

In de view, onder de `<h1>`:
```html
@if ($gebeurtenis->samenvatting)
    <h2>Kernfeiten</h2>
    <p>{{ $gebeurtenis->samenvatting->kernfeiten }}</p>

    <h2>Betrokkenen</h2>
    <p>{{ $gebeurtenis->samenvatting->betrokkenen }}</p>

    <h2>Overeenstemming</h2>
    <p>{{ $gebeurtenis->samenvatting->overeenstemming }}</p>

    <h2>Verschil</h2>
    <p>{{ $gebeurtenis->samenvatting->verschil }}</p>
@else
    <p>Deze gebeurtenis heeft nog geen samenvatting.</p>
@endif
```

> [!note] Een `hasOne` die ontbreekt is geen lege string, het is `null`. Zonder `@else` crasht PHP op `->kernfeiten` van `null`. De vier namen zijn de kolommen in `samenvattingen`. `{{ }}` escaped HTML uit de AI-tekst.

Check: een `gebeurtenis_id` in `samenvattingen` toont dezelfde vier teksten als phpMyAdmin. Een id dat daar niet in staat: onderwerp plus de zin, geen fout, geen lege `<h2>`-blokken.

## Artikelen inclusief bron: geneste eager load
Eén samenvatting lui laden is één extra query. Per artikel de bron lui laden is N+1.

**Laravel-concept:** de punt in `'artikelen.bron'` is nesten, net als `view('gebeurtenissen.show')`. `artikelen` is de `hasMany` op `Gebeurtenis`, `bron` de `belongsTo` op `Artikel`.
```php
$gebeurtenis->load('samenvatting', 'artikelen.bron');
```

`load()` mag meerdere relaties als aparte strings. `samenvatting` blijft erin, zodat die niet lui blijft.

Artikelen staan bij mij **boven** de samenvatting. De casus zegt niks over die volgorde.
```html
<h2>Artikelen</h2>
<ul>
    @foreach ($gebeurtenis->artikelen as $artikel)
        <li>
            <a href="{{ $artikel->url }}">{{ $artikel->titel }}</a>
            ({{ $artikel->bron->naam }})
        </li>
    @endforeach
</ul>
```

`$artikel->url` is de originele nieuwssite, geen interne Laravel-route.

Check: aantal `<li>`s = aantal rijen in `artikelen` met dat `gebeurtenis_id`. Titel en `bronnen.naam` kloppen. De link opent de echte URL.

## Groeperen op orientatie
`$gebeurtenis->artikelen` is na `load()` een **Collection**, geen SQL `GROUP BY`. Ik tel niet samen, ik zet rijen in bakjes voor de HTML. Dat hoort in de controller, niet in Blade.
```php
$artikelenPerOrientatie = $gebeurtenis->artikelen->groupBy(function ($artikel) {
    return $artikel->bron->orientatie;
});

return view('gebeurtenissen.show', [
    'gebeurtenis' => $gebeurtenis,
    'artikelenPerOrientatie' => $artikelenPerOrientatie,
]);
```

De returnwaarde van de closure wordt de sleutel. Fox News en The Daily Signal komen onder `right`. Dat kan alleen omdat `bron` al geladen is.

Geneste `@foreach`: buitenste loop is groepen, binnenste is artikelen.
```html
<h2>Artikelen</h2>
@foreach ($artikelenPerOrientatie as $orientatie => $artikelen)
    <h3>{{ $orientatie }}</h3>
    <ul>
        @foreach ($artikelen as $artikel)
            <li>
                <a href="{{ $artikel->url }}">{{ $artikel->titel }}</a>
                ({{ $artikel->bron->naam }})
            </li>
        @endforeach
    </ul>
@endforeach
```

`{{ $orientatie }}` print `left-center`, niet “links”. Een oriëntatie zonder artikelen krijgt geen `<h3>`.

Check: elke kop is exact de databasewaarde. Elk artikel staat onder de `orientatie` van **zijn** bron. Totaal aantal links blijft gelijk.

## Bundelen naar Links / Midden / Rechts
De casus wil bakjes voor de lezer, en de Media Bias Fact Check-label behouden. De kolom `bronnen.orientatie` wijzig ik niet. The Nation blijft `left`.

De array is de enige plek waar “Links” bestaat:
```php
$bakjes = [
    'left' => 'Links',
    'left-center' => 'Links',
    'neutral' => 'Midden',
    'right-center' => 'Rechts',
    'right' => 'Rechts',
];

$artikelenPerOrientatie = $gebeurtenis->artikelen->groupBy(function ($artikel) use ($bakjes) {
    $orientatie = $artikel->bron->orientatie;

    return $bakjes[$orientatie] ?? $orientatie;
});
```

PHP-concept: `use ($bakjes)` is nodig omdat een closure lokale variabelen niet automatisch ziet.

`?? $orientatie` vangt een waarde die niet in de map zit: dan blijft de ruwe string de groepsnaam, in plaats van een crash op een ontbrekende key.

In Blade heet de buitenste key `$bakje` (weergave), niet `$orientatie` (database). De MBFC-label blijft per artikel staan, anders verdwijnt `left` vs `left-center`.
```html
@foreach ($artikelenPerOrientatie as $bakje => $artikelen)
    <h3>{{ $bakje }}</h3>
    <ul>
        @foreach ($artikelen as $artikel)
            <li>
                <a href="{{ $artikel->url }}">{{ $artikel->titel }}</a>
                ({{ $artikel->bron->naam }}, {{ $artikel->bron->orientatie }})
            </li>
        @endforeach
    </ul>
@endforeach
```

The Nation en NYT Politics kunnen onder dezelfde `<h3>Links</h3>` staan. Achter de titel blijft `left` vs `left-center`.

Check: koppen zijn `Links` / `Midden` / `Rechts`. phpMyAdmin `bronnen.orientatie` is onveranderd.

## Volgorde van bakjes: sortBy
`groupBy` zet bakjes in de volgorde van het **eerste** artikel in de Collection. Een Fox-artikel met lager `id` dan NYT zet “Rechts” boven “Links”.

`sortBy` is een tweede Collection-stap, ná het groeperen. De strings moeten exact gelijk zijn aan de bakjes (`Links`, niet `links`).
```php
$volgorde = [
    'Links' => 1,
    'Midden' => 2,
    'Rechts' => 3,
];
$artikelenPerOrientatie = $artikelenPerOrientatie->sortBy(function ($artikelen, $bakje) use ($volgorde) {
    return $volgorde[$bakje] ?? 4;
});
```

**Laravel-concept:** `sortBy` op een gegroepeerde Collection krijgt de value (`$artikelen`) en de key (`$bakje`). Sorteergetal 1, 2, 3 is links naar rechts. `?? 4` zakt een onbekend bakje naar onderen.

`sortBy` maakt een nieuwe Collection, daarom opnieuw toewijzen. Een bakje zonder artikelen blijft weg: geen Midden betekent Links, daarna Rechts. Geen lege `<h3>`.

Check: koppen van boven naar beneden Links, Midden (als die er is), Rechts, ook als een `right`-artikel het laagste `artikelen.id` heeft.

## Links vanaf het overzicht
Hardcoded `/gebeurtenissen/{{ $gebeurtenis->id }}` breekt als het pad later wijzigt. Laravel-conventie: named route.

Alleen de `show`-regel:
```php
Route::get('/gebeurtenissen/{gebeurtenis}', [GebeurtenisController::class, 'show'])
    ->name('gebeurtenissen.show');
```

`gebeurtenissen.show` is geen view-naam en geen URL. Het is een label. `php artisan route:list` toont die naam in de kolom Name.

In `index.blade.php` alleen het onderwerp wrappen:
```html
<a href="{{ route('gebeurtenissen.show', $gebeurtenis) }}">
    {{ $gebeurtenis->onderwerp }}
</a>
```

`route('gebeurtenissen.show', $gebeurtenis)` vult `{gebeurtenis}` met het `id`. Gebeurtenissen zonder samenvatting krijgen dezelfde link. De lege staat zit al in `show`.

Check: klikken op een rij mét samenvatting toont vier velden en bakjes. Klikken op een rij zonder samenvatting toont de zin, geen crash. Adresbalk is `/gebeurtenissen/{id}`.

## Waarom ik het zo heb aangepakt
Zelfde scheiding als bouwblok 6: route, controller, Blade. Eerst een platte string, dan een lege view, dan samenvatting, dan artikelen, dan groeperen, dan bakjes, dan sorteren, dan de link. Elke stap één concept (binding, `load` vs `with`, N+1, Collection `groupBy`, `use` in een closure, `sortBy`, named route).

## Beperkingen om te onthouden
- Aan het eind van dit bouwblok waren `index` en `show` nog losse HTML-documenten. Gedeelde layout, Tailwind, terug-link en `gebeurtenissen.index` staan in notitie 8. De bronnaam staat daar op een eigen regel onder de titel. De MBFC-label blijft erbij.
- Een leeg bakje kreeg hier geen kop. Sinds notitie 9 zijn Links, Midden en Rechts er altijd, met een zin als het bakje leeg is, en staan ze naast elkaar vanaf 768px.
- Bakjes zijn weergave. `bronnen.orientatie` blijft de dataset-label.
- `groupBy` alleen is niet gesorteerd. Zonder `sortBy` hangt de koppen-volgorde af van welk artikel eerst komt.
- Een onbekende `orientatie` valt via `??` buiten de drie bakjes.
- Pagina’s via `php artisan serve` (PHP 8.4). XAMPP Apache blijft 8.2.

## Latere uitbreiding: beeldkaarten (bouwblok 14)
De oorspronkelijke detailpagina toonde alleen titels, bron en label. Nu staat ieder artikel in een kaart met een vaste 16:9-afbeeldingsruimte. De afbeelding komt uit `artikelen.afbeelding_url`; als die ontbreekt of niet laadt, blijft “Geen afbeelding beschikbaar” staan. De titel blijft een link naar het oorspronkelijke artikel.

Onder de titel staan de bronnaam, het ruwe MBFC-label en de publicatiedatum. `artikelen.afbeelding_credit` wordt alleen getoond als er een credit beschikbaar is. De artikelen blijven in Links, Midden, Rechts en Onbekend gegroepeerd; de visuele wijziging verandert de labels of groepering niet. De samenvatting staat nog steeds onder de artikelkolommen.

Zie `14. Visuele vormgeving en artikelafbeeldingen.md` voor de RSS-velden, fallbacks, lazy loading en open punten rond alt-tekst en beeldrechten.

## Latere uitbreiding: preview, bronlinks en gerelateerd (bouwblok 17)
- **Bakjes op het model.** De `$bakjes`-array hierboven staat niet meer in de controller. Hij is een methode `Bron::bakje()` geworden, omdat ook de bronpagina's hem nodig hebben. De controller doet nu `groupBy(fn ($artikel) => $artikel->bron?->bakje() ?? 'Onbekend')`. Zelfde uitkomst, één plek.
- **Preview.** Elke kolom toont eerst 3 artikelen (`$aantalPreview`). Eén knop onder de kolommen ("Toon alle X artikelen") klapt de rest in alle kolommen uit. Zonder JavaScript is alles zichtbaar.
- **Per artikel** staat nu de RSS-omschrijving onder de titel (200 tekens), opent de titel in een nieuw tabblad (`target="_blank" rel="noopener noreferrer"`), en linkt de bronnaam naar `/bronnen/{bron}`.
- **Samenvatting** toont datum en model.
- **Gerelateerde gebeurtenissen** onder de samenvatting: de 3 gebeurtenissen waarvan de artikelen inhoudelijk het meest op deze lijken, via de embeddings.

Zie notitie 17.
