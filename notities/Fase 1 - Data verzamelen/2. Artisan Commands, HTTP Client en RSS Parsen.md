#laravel #cheatsheet #medialens

Uitleg voor mezelf van wat ik gedaan heb bij bouwblok 2 van de MediaLens casus: een eigen Artisan command bouwen dat artikelen ophaalt uit RSS-feeds en opslaat in de database.

## Wat is een Artisan command
Een Artisan command is een stukje code dat ik vanaf de terminal kan aanroepen, op dezelfde manier als ingebouwde commando's zoals `php artisan migrate`.
```bash
php artisan make:command ArtikelenOphalen
```

Dit maakt `app/Console/Commands/ArtikelenOphalen.php` aan.
```php
class ArtikelenOphalen extends Command
{
    protected $signature = 'artikelen:ophalen';
    protected $description = 'Haalt artikelen op bij alle bronnen met een feed-URL.';

    public function handle()
    {
        $this->info('Het command werkt.');
    }
}
```

`$signature` is de naam waarmee ik het command aanroep. `handle()` is de methode die uitgevoerd wordt zodra ik het command draai. `$this->info()` print een groene regel, `$this->line()` print een gewone regel, `$this->warn()` print een gele waarschuwing.

> [!warning] Sommige Laravel versies genereren automatisch een `#[Signature(...)]` en `#[Description(...)]` attribute bovenaan de class, naast de gewone `$signature` en `$description` properties. Als die twee niet hetzelfde zeggen, spreekt Laravel zichzelf tegen en herkent hij het command niet goed. Ik verwijder die attributes en houd alleen de properties aan.

## Bronnen ophalen met Eloquent
```php
use App\Models\Bron;

$bronnen = Bron::whereNotNull('feed_url')->get();
```

`whereNotNull('feed_url')` filtert automatisch de bronnen eruit waar nog geen feed-URL bekend is. `->get()` voert de query uit en geeft een collection terug.

## De HTTP client
Laravel heeft een ingebouwde HTTP client, geen los package nodig.
```php
use Illuminate\Support\Facades\Http;

$response = Http::get($bron->feed_url);
$response->status();   // bijvoorbeeld 200
$response->body();     // de ruwe inhoud als string
```

## RSS parsen met SimpleXML

Een RSS-feed is gewoon XML. PHP heeft hier een ingebouwde functie voor.
```php
$xml = simplexml_load_string($response->body());

foreach ($xml->channel->item as $item) {
    $titel = (string) $item->title;
    $url = (string) $item->link;
}
```

Elke RSS-feed heeft de structuur `<rss><channel><item>...</item></channel></rss>`, dus `$xml->channel->item` is de lijst met losse artikelen.

> [!note] `$item->title` is geen gewone string maar een `SimpleXMLElement` object. Door er `(string)` voor te zetten dwing ik PHP om er een echte string van te maken. Zonder die cast geeft opslaan in de database later rare fouten.

## Datum omzetten

Een feed levert de datum aan als tekst, bijvoorbeeld `Tue, 30 Sep 2026 14:00:00 GMT`, dat is niet het formaat dat mijn `date` kolom verwacht.
```php
$publicatiedatum = date('Y-m-d', strtotime((string) $item->pubDate));
```

`strtotime()` zet de tekst om in een Unix timestamp, `date('Y-m-d', ...)` maakt daar `2026-09-30` van.

## Duplicaten voorkomen
Als ik het command later vaker draai, wil ik niet elke keer dezelfde artikelen opnieuw opslaan.
```php
if (Artikel::where('url', $url)->exists()) {
    continue;
}
```

De URL is uniek per artikel, dus die gebruik ik als check. `continue` slaat de rest van de loop-iteratie over en gaat door naar het volgende item.

## Opslaan en mass assignment
```php
Artikel::create([
    'titel' => $titel,
    'publicatiedatum' => $publicatiedatum,
    'volledige_tekst' => $tekst,
    'url' => $url,
    'bron_id' => $bron->id,
]);
```

Dit gaf eerst een `MassAssignmentException`. Laravel staat standaard niet toe dat `create()` zomaar elk veld invult, dat is een beveiliging tegen het per ongeluk (of moedwillig, bijvoorbeeld via een formulier) overschrijven van velden die daar niet voor bedoeld zijn. Ik moet zelf opgeven welke velden wel via `create()` mogen worden ingevuld:
```php
class Artikel extends Model
{
    protected $table = 'artikelen';

    protected $fillable = [
        'titel',
        'publicatiedatum',
        'volledige_tekst',
        'url',
        'bron_id',
        'gebeurtenis_id',
    ];
}
```

> [!tip] Dit moet ik onthouden: elk model waar ik `create()` of `update()` op gebruik heeft een `$fillable` array nodig met de velden die ik echt via die methodes wil kunnen zetten.

## RSS-omschrijving schoonmaken
Guardian en LA Times zetten `<p>` en links in `description`. ABC en France 24 hebben extra enters. Guardian eindigt op `Continue reading...`. The Nation (en andere WordPress-feeds) eindigt op `The post {titel} appeared first on The Nation .`. Guardian Australia zet tussen standfirst en alinea promo-regels in `<li><p>…</p></li>`: *Get our breaking news email, free app or daily news podcast* (soms *new political email*) en soms *Listen to the podcast {wisselende titel}*. Dat is geen artikeltekst. De feed-URL in de seeder is wel goed; de rommel zit in het RSS-veld.

Schoonmaken gebeurt bij het ophalen, vóór `create()`, voor elke bron. Geen uitzondering per bron. Als ik dit alleen in de matcher filter, blijft de zin in de database staan en ziet de AI hem later ook.

De volgorde is het leermoment: eerst HTML-entiteiten decoderen, dan de Guardian-`<li>`-promo's eraf **zolang de tags er nog zijn**, daarna pas tags naar spaties.
```php
$tekst = (string) $item->description;
$tekst = html_entity_decode($tekst, ENT_QUOTES | ENT_HTML5, 'UTF-8');
$tekst = preg_replace('/<li>\s*<p>\s*Get our\b.*?<\/li>/is', ' ', $tekst);
$tekst = preg_replace('/<li>\s*<p>\s*Listen to the podcast\b.*?<\/li>/is', ' ', $tekst);
$tekst = preg_replace('/<[^>]+>/', ' ', $tekst);
$tekst = preg_replace('/\s+/', ' ', $tekst);
$tekst = preg_replace('/Continue reading\.?\.?\.?\s*$/i', '', $tekst);
$tekst = preg_replace('/\s*The post .+? appeared first on .+$/i', '', $tekst);
$tekst = trim($tekst);
```

- `html_entity_decode`: `&amp;` wordt `&`, en `&lt;li&gt;` wordt een echte `<li>`. Zelfde call als bij titels in de matcher. Zonder deze stap eerst ziet de `<li>`-regex niks.
- Guardian-promo's als HTML-`<li>`: in de feed staat `Get our <a>breaking news email</a>, <a>free app</a> or …`. `</a>` vlak voor de komma wordt ná tag-strip een spatie (`email ,`). Een tekstfilter op `email,?` (komma direct achter email) matcht dan niet. Daarom haal ik het hele `<li>` weg vóór tags naar spaties.
- `Listen to the podcast` heeft een wisselende titel (`Alan Jones on Trial`, een andere serie, …). `.+?` tot de eerste `</li>` pakt die titel mee zonder dat ik hem hoef te kennen. De `s` na `/i` laat de punt ook over een regeleinde matchen.
- Tags naar een spatie, niet `strip_tags`: anders plakt `arrest.</p><p>A` aan elkaar tot `arrest.A`.
- `/\s+/` naar één spatie: enters en tabs plat.
- `Continue reading` alleen aan het **einde** (`$`), anders gooi ik die woorden midden in een zin weg.
- `The post ... appeared first on ...` is een WordPress-footer. `.+?` is de wisselende titel ertussen; de `?` stopt bij de eerste `appeared first on`. De sitenaam tot het einde (`$`) gaat mee, niet alleen `The Nation`. Korte Nation-omschrijvingen vallen binnen de eerste 40 woorden van de matcher. Zonder deze regel delen alle Nation-items al `post`, `appeared`, `first` en `nation` (4 van de 7 trefwoorden), plus de titel nog eens.
- Zonder de `<li>`-regels delen Guardian-AU-items `get`, `our`, `email`, `free`, `app`, `daily`, `news`, `podcast` (8 trefwoorden, toen drempel 7). De matcher groepeerde dan kolenmijn, immigratie en moordzaken als één gebeurtenis. ABC over dezelfde NSW-kolenmijn kon terecht in die groep; de rest liftte mee. RAKE (`en_US`) knipt nu `get`/`our` weg; de `<li>`-strip blijft de fix. Actuele drempel: notitie 3.

`strip_tags` haalt geen zinnen weg, alleen tags. Extra frases voeg ik pas toe als ik ze in de echte feed of in phpMyAdmin zie.

### Uitbreiding bij bouwblok 15: afsluiters van nieuwe bronnen
Bij het uitbreiden naar 124 bronnen kwamen vier nieuwe herhaalde afsluiters boven. Ze staan ná `The post ...`, vóór `trim()`:
```php
$tekst = preg_replace('/\s*The post .+? (?:appeared first|first appeared) on .+$/i', '', $tekst);
$tekst = preg_replace('/\s*Like Blaze News\?.*$/i', '', $tekst);
$tekst = preg_replace('/\s*Our Standards: The GB News Editorial Charter\s*$/i', '', $tekst);
$tekst = preg_replace('/\s*Read More:\s*https?:\/\/\S+\s*$/i', '', $tekst);
$tekst = preg_replace('/\s*\[(?:…|\.\.\.)\]\s*$/u', '…', $tekst);
```

- Mediaite zet de woorden andersom: `first appeared on` in plaats van `appeared first on`. `(?:a|b)` is een groep zonder opslag, die één van beide accepteert.
- TheBlaze eindigt bijna elk item op *Like Blaze News? Bypass the censors, sign up for our newsletters… Sign up here!*. `\?` is een letterlijk vraagteken. Alles vanaf die zin tot het einde gaat weg.
- GB News eindigt elk item op *Our Standards: The GB News Editorial Charter*.
- Punch eindigt op *Read More: https://punchng.com/…*. De regel vereist een link (`https?:\/\/\S+`) en het einde (`$`), zodat een zin als *The campaign is called Read More: Books for Everyone* blijft staan.
- WordPress-samenvattingen eindigen op `[…]` (`&#8230;` wordt door `html_entity_decode` een echt `…`-teken). Die vervang ik door `…`, zodat de lezer nog ziet dat de tekst is afgekapt. De `u` achter de regex is nodig omdat `…` een UTF-8-teken van meerdere bytes is.

Alle vijf staan op `$`: alleen aan het einde. De regels hebben een naam van een bron in het commentaar, maar gelden voor elke feed. Dat is dezelfde keuze als bij de Guardian-promo's: geen uitzondering per bron.

`tests/Feature/ArtikelenOphalenTest.php` test elke regel met een nagebootste feed via `Http::fake()`. Een data provider geeft per geval een `description` en de verwachte `volledige_tekst`.

> [!warning] Eerste poging: tekstfilter ná tag-strip op `Get our (?:new political|breaking news) email,? …`. Die regex is te strikt op de komma. Leermoment: na `preg_replace('/<[^>]+>/', ' ', …)` is `</a>,` geworden tot ` ,`. Kijk in phpMyAdmin naar de echte `volledige_tekst`, niet naar hoe de zin in de browser of in de ruwe HTML staat.

> [!warning] De duplicaatcheck op URL slaat bestaande rijen over. Oude `volledige_tekst` blijft vies tot `migrate:fresh --seed` plus opnieuw ophalen, of tot ik die rijen zelf bijwerk (`REPLACE` in phpMyAdmin, daarna `gebeurtenis_id` leegmaken en opnieuw `koppel()`, zie notitie 3). Een nieuwe regex verandert dus geen Nation- of Guardian-artikelen die er al in staan. Testen: `volledige_tekst` van een verse Guardian-AU-rij openen: *Get our …* en *Listen to the podcast …* mogen er niet in staan, de echte alinea wel.

## Het volledige command
```php
public function handle()
{
    $bronnen = Bron::whereNotNull('feed_url')->get();

    foreach ($bronnen as $bron) {
        $this->info("Ophalen bij {$bron->naam}...");

        $response = Http::get($bron->feed_url);
        $xml = simplexml_load_string($response->body());

        foreach ($xml->channel->item as $item) {
            $titel = (string) $item->title;
            $url = (string) $item->link;
            $publicatiedatum = date('Y-m-d', strtotime((string) $item->pubDate));
            $tekst = (string) $item->description;
            $tekst = html_entity_decode($tekst, ENT_QUOTES | ENT_HTML5, 'UTF-8');
            $tekst = preg_replace('/<li>\s*<p>\s*Get our\b.*?<\/li>/is', ' ', $tekst);
            $tekst = preg_replace('/<li>\s*<p>\s*Listen to the podcast\b.*?<\/li>/is', ' ', $tekst);
            $tekst = preg_replace('/<[^>]+>/', ' ', $tekst);
            $tekst = preg_replace('/\s+/', ' ', $tekst);
            $tekst = preg_replace('/Continue reading\.?\.?\.?\s*$/i', '', $tekst);
            $tekst = preg_replace('/\s*The post .+? appeared first on .+$/i', '', $tekst);
            $tekst = trim($tekst);

            if (Artikel::where('url', $url)->exists()) {
                continue;
            }

            Artikel::create([
                'titel' => $titel,
                'publicatiedatum' => $publicatiedatum,
                'volledige_tekst' => $tekst,
                'url' => $url,
                'bron_id' => $bron->id,
            ]);

            $this->line("- {$titel} ({$publicatiedatum})");
        }
    }

    $this->info('Klaar.');
}
```
## Foutafhandeling
Een bron kan om drie verschillende redenen falen. Elke reden heeft een eigen controle nodig, en bij alle drie gebruik ik `continue` zodat één kapotte bron de rest niet blokkeert.

### 1. Geen verbinding: try/catch
Als de server niet bereikbaar is (verkeerd domein, geen internet, timeout), komt er geen response. Laravel gooit dan een `ConnectionException`.
```php
use Illuminate\Http\Client\ConnectionException;

try {
    $response = Http::get($bron->feed_url);
} catch (ConnectionException $e) {
    $this->error("Geen verbinding met {$bron->naam}: {$e->getMessage()}");
    continue;
}
```

`try` voert de code uit, en bij een exception springt PHP naar `catch` in plaats van te crashen. Ik vang bewust alleen `ConnectionException` af, zodat echte bugs in mijn eigen code nog zichtbaar blijven.

> [!warning] Zonder `use Illuminate\Http\Client\ConnectionException;` bovenaan zoekt PHP de klasse in de eigen namespace (`App\Console\Commands`). Die bestaat niet. Het verraderlijke is dat dit pas misgaat op het moment dat de fout echt optreedt. De code draait gewoon zolang alles werkt, en daarna lijkt het alsof de `try/catch` er niet staat. Als een `catch` zich gedraagt alsof hij er niet is, eerst controleren of de klasse geïmporteerd is.

### 2. Een foutstatus: failed()
Als de server wel antwoordt, maar met een 4xx of 5xx.
```php
if ($response->failed()) {
    $this->error("Fout bij ophalen bij {$bron->naam}: {$response->status()}");
    continue;
}
```

`failed()` is `true` bij een 4xx- of 5xx-status. Het tegenovergestelde is `successful()`.

> [!note] De HTTP client onderscheidt dus twee soorten fouten. Een foutstatus is een response die ik met `failed()` controleer. Een verbindingsprobleem is een exception die ik met `try/catch` afvang. Ik heb allebei nodig.

### 3. Kapotte of lege XML bij een status 200
Een bron kan 200 teruggeven met een HTML-pagina, een inlogscherm of een lege body. `failed()` ziet dat als gelukt.
```php
libxml_use_internal_errors(true);
$xml = simplexml_load_string($response->body());

if ($xml === false) {
    $this->error("Ongeldige XML van {$bron->naam}, bron overgeslagen.");
    continue;
}
```

`simplexml_load_string` geeft bij ongeldige XML `false` terug, maar gooit eerst een PHP-waarschuwing. Laravel zet waarschuwingen om in een `ErrorException`, dus het command crasht nog voordat ik de `false` kan controleren. `libxml_use_internal_errors(true)` zet die waarschuwing uit, zodat ik gewoon `false` terugkrijg. Ik gebruik `===` (drie tekens) zodat alleen echt `false` telt.

> [!tip] PHP-functies melden fouten op twee manieren: met een returnwaarde (`false`) of met een waarschuwing. In Laravel is een controle op `false` alleen dus niet genoeg, ik moet ook de waarschuwing afvangen of uitzetten.

### Testen
Ik test elke controle door in phpMyAdmin tijdelijk een `feed_url` te vervangen, en daarna weer terug te zetten:
- `https://thehill.com/news/bestaat-niet-123/` voor een foutstatus
- `https://bestaat-niet.invalid/feed` voor geen verbinding (`.invalid` wordt per internetstandaard nooit opgelost)
- `https://example.com` voor HTML in plaats van XML

> [!note] Bekende beperking: is de XML wel geldig maar geen RSS (bijvoorbeeld een Atom-feed zonder `channel`), dan is `$xml` geen `false`. De `foreach` doet dan niets en ik zie geen foutmelding. Afvangen kan later met `isset($xml->channel->item)`. Bij bouwblok 15 vielen hierdoor Vox, The Atlantic, Jacobin en Business Insider af (Atom, root `<feed>`) en Nikkei Asia en Taipei Times (RDF).

## Totalen per bron
Eerst printte ik per nieuw artikel een regel met titel en datum. Na het groeperen kwam daar vanuit `koppel()` nog een `echo` bij (`Match:` of `Nieuwe gebeurtenis:`). Twee regels per artikel, en de `echo` ging buiten `$this->line()` om.

De matcher geeft nu een string terug (`nieuw`, `bestaand` of `overgeslagen`). Het command telt. De tellers staan in de bron-lus, zodat elke bron weer bij 0 begint. Alleen een artikel dat net is opgeslagen telt mee. Een URL die al in de database staat, slaat de duplicaatcheck over vóór `create()`.

```php
$opgehaald = 0;
$nieuw = 0;
$bestaand = 0;

$resultaat = $matcher->koppel($artikel);

$opgehaald++;
if ($resultaat === 'nieuw') {
    $nieuw++;
} elseif ($resultaat === 'bestaand') {
    $bestaand++;
}

$this->line("{$opgehaald} nieuwe artikelen, {$nieuw} nieuwe gebeurtenissen, {$bestaand} bij een bestaande gebeurtenis.");
```

Die laatste regel staat ná de item-lus. Erboven blijft `Ophalen bij {$bron->naam}...`, zodat ik tijdens het HTTP-verzoek zie welke bron bezig is.

`$opgehaald` is het aantal nieuwe artikelen. Nieuwe gebeurtenissen plus koppelingen aan een bestaande gebeurtenis is datzelfde aantal. `overgeslagen` telt hier niet apart mee. Dit command roept `koppel()` alleen aan op een net aangemaakt artikel, dus die tak kom ik hier niet tegen.

Een tweede run van `php artisan artikelen:ophalen` hoort per bron drie nullen te tonen, zonder titelregels en zonder `Match:`.

## Latere uitbreiding: afbeeldingen uit RSS (bouwblok 14)
Naast `description` leest `ArtikelenOphalen` nu afbeeldingsmetadata uit `media:content`, `media:thumbnail` en `enclosure`. Bij `enclosure` wordt alleen een afbeelding geaccepteerd; audio zoals `audio/mpeg` wordt genegeerd. De URL moet geldig zijn en `http` of `https` gebruiken. Zie `14. Visuele vormgeving en artikelafbeeldingen.md` voor de volledige uitleg en checks.

De kolommen `afbeelding_url` en `afbeelding_credit` zijn optioneel. `media:credit` wordt opgeslagen als de feed die levert. Bij een bestaand artikel vult een volgende run de afbeeldingsvelden alleen aan als de afbeelding nog ontbreekt. De artikel-URL blijft de duplicaatsleutel; een oud artikel wordt dus alleen bijgewerkt zolang het nog in de actuele feed voorkomt.

## Latere uitbreiding: tijd, titel en parallel ophalen (bouwblok 17)
Drie dingen in dit command zijn veranderd. Het volledige command hierboven is de versie van toen.

- **Tijd erbij.** `date('Y-m-d H:i:s', strtotime(...))` in plaats van `'Y-m-d'`. De kolom is nu een `datetime` en de app staat op `Europe/Amsterdam`, dus een `pubDate` van 08:15 GMT wordt 10:15. Een bestaand artikel dat nog op `00:00:00` staat, krijgt bij een volgende run de echte tijd, net als de afbeeldingen hieronder.
- **Titel getrimd.** `trim((string) $item->title)`. Sommige feeds zetten een enter achter de titel, en die kwam dan ook in het onderwerp van de gebeurtenis.
- **Feeds parallel.** Eerst alle feeds ophalen met `Http::pool()`, maximaal 10 tegelijk, daarna per bron verwerken zoals eerst. 124 feeds in ±11 seconden.

Dat laatste verandert de foutafhandeling van stap 1 hierboven. In een pool wordt een verbindingsfout niet gegooid, hij komt terug als exception-object in de lijst met antwoorden. De `try`/`catch` vangt dan niks. Nu:
```php
if ($response instanceof Throwable) {
    $this->error("Geen verbinding met {$bron->naam}: {$response->getMessage()}");
    continue;
}
```

Stap 2 (`failed()`) en stap 3 (kapotte XML) zijn hetzelfde gebleven. Zie notitie 17.

## Beperking om te onthouden
Een RSS-feed geeft meestal alleen een titel en een korte samenvatting terug in `description`, niet de volledige artikeltekst. Mijn `volledige_tekst` kolom is dus voorlopig niet echt de volledige tekst. Dit moet ik meenemen bij bouwblok 4 en 5, of ik moet in een latere stap de artikelpagina zelf ook nog scrapen. HTML, `Continue reading...`, `The post ... appeared first on ...` en de Guardian-`<li>`-promo's (`Get our …`, `Listen to the podcast …`) haal ik er bij het ophalen al af, zodat phpMyAdmin, de matcher en de AI dezelfde schone zin zien. De `<li>`-regels staan vóór tag-strip; een tekstfilter ná tags mist `email ,`.

## Wat ik ook geleerd heb: dode feeds
Niet elke RSS-URL die ik vind is nog actief. Een feed kan een status 200 teruggeven en toch verouderde of bevroren data bevatten, bijvoorbeeld een CNN feed die ik tegenkwam met alleen artikelen uit 2023. Status 200 betekent dus alleen dat de URL bereikbaar is, niet dat de inhoud actueel is. Ik controleer dat door te kijken of de publicatiedatums van de opgehaalde items ook echt recent zijn.

Bij bouwblok 15 kwam hetzelfde terug bij The Wall Street Journal (`feeds.a.dj.com`) en Voice of America: status 200, geldige XML, maar het nieuwste item was meer dan een jaar oud. Hoe ik 212 feeds in één keer getest heb, staat in notitie 15.
