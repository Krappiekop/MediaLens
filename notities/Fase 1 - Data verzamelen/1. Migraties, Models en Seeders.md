#laravel #cheatsheet #medialens

Uitleg voor mezelf van wat ik gedaan heb bij bouwblok 1 van de MediaLens casus: het databasemodel opzetten met migraties, Eloquent models en een seeder.

## Wat is een migratie
Een migratie is een PHP bestand dat beschrijft hoe een tabel in de database eruit moet zien. In plaats van zelf in phpMyAdmin een tabel te klikken, schrijf ik het in code, zodat iedereen die het project clonet met een commando dezelfde database kan opbouwen.
```php
public function up(): void
{
    Schema::create('bronnen', function (Blueprint $table) {
        $table->id();
        $table->string('naam');
        $table->string('orientatie');
        $table->timestamps();
    });
}
```

`$table->id()` maakt een auto-increment primary key aan. `$table->timestamps()` voegt automatisch `created_at` en `updated_at` toe, dat hoef ik zelf niet bij te houden.

Voor een koppeling naar een andere tabel gebruik ik `foreignId()->constrained()`, bijvoorbeeld in de artikelen tabel:
```php
$table->foreignId('bron_id')->constrained('bronnen');
```

Dit maakt in een keer de kolom `bron_id` aan en zet er een foreign key constraint op naar de `id` kolom van `bronnen`. Dat voorkomt dat ik per ongeluk een artikel aan een bron koppel die niet bestaat.

> [!tip] De volgorde waarin ik migraties aanmaak is belangrijk. Laravel voert ze uit in de volgorde van hun bestandsnaam (die begint met een timestamp), dus `bronnen` en `gebeurtenissen` moet ik eerder aanmaken dan `artikelen`, want die verwijst naar allebei.

## Migraties draaien
```bash
php artisan migrate
```

Dit voert alle migraties uit die nog niet gedraaid zijn. Tijdens het ontwikkelen gebruik ik vaker:
```bash
php artisan migrate:fresh --seed
```

Dit breekt de hele database af, bouwt alle tabellen opnieuw op, en vult ze meteen met de seeder. Handig als ik iets in een migratie aanpas en gewoon opnieuw wil beginnen, dit ben ik nog niet in productie dus data verlies ik toch niet iets dat ertoe doet.

## Wat is een Eloquent model
Een model is de PHP klasse waarmee ik met een tabel praat, zonder zelf SQL te schrijven. Elk model hoort bij een tabel.
```bash
php artisan make:model Bron
```

Laravel verwacht standaard dat het model `Bron` hoort bij de tabel `brons`, hij maakt zelf een Engels meervoud van de klassenaam. Bij Nederlandse namen klopt dat niet, `bronnen` wordt dan niet herkend. Dit ben ik letterlijk tegengekomen: mijn seeder gaf een foutmelding dat tabel `brons` niet bestond, terwijl mijn migratie `bronnen` had aangemaakt.

De oplossing is de tabelnaam zelf opgeven in het model:
```php
class Bron extends Model
{
    protected $table = 'bronnen';
}
```

> [!note] Dit moet ik onthouden voor elk volgend project met Nederlandse tabelnamen: `$table` altijd zelf zetten, Laravel raadt het anders fout.

## Relaties tussen models
In mijn datamodel heeft een Bron meerdere Artikelen, en hoort een Artikel bij precies een Bron. Dat soort relaties leg ik vast als methodes op het model, niet als losse kolommen.

**hasMany**, voor de kant met meerdere gekoppelde records:
```php
class Bron extends Model
{
    protected $table = 'bronnen';

    public function artikelen()
    {
        return $this->hasMany(Artikel::class);
    }
}
```

**belongsTo**, voor de kant die naar een enkel record verwijst (de kant met de foreign key kolom):
```php
class Artikel extends Model
{
    protected $table = 'artikelen';

    public function bron()
    {
        return $this->belongsTo(Bron::class);
    }
}
```

**hasOne**, als het precies een op een is, zoals bij Gebeurtenis en Samenvatting:
```php
class Gebeurtenis extends Model
{
    protected $table = 'gebeurtenissen';

    public function samenvatting()
    {
        return $this->hasOne(Samenvatting::class);
    }
}
```

Dankzij deze relaties kan ik straks bijvoorbeeld `$bron->artikelen` gebruiken om alle artikelen van een bron op te halen, zonder zelf een JOIN te schrijven.

## Wat is een seeder
Een seeder vult de database met startdata. Ik gebruik dit voor de bronkleur-tabel, want die vul ik zelf, niet automatisch.
```bash
php artisan make:seeder BronSeeder
```

```php
class BronSeeder extends Seeder
{
    public function run(): void
    {
        Bron::insert([
            ['naam' => 'CNN', 'orientatie' => 'left'],
            ['naam' => 'Reuters', 'orientatie' => 'neutral'],
        ]);
    }
}
```

Een seeder draait niet automatisch mee met `migrate`, ik moet hem koppelen in `DatabaseSeeder.php`:
```php
class DatabaseSeeder extends Seeder
{
    public function run(): void
    {
        $this->call(BronSeeder::class);
    }
}
```
Daarna draait `php artisan migrate:fresh --seed` de seeder automatisch mee.

> [!warning] `Bron::insert` controleert niet of een bron al bestaat. `php artisan db:seed` op een gevulde database zet alle bronnen er dubbel in. Daarom altijd `migrate:fresh --seed`, of een aparte seeder met `firstOrCreate` op `feed_url` als ik de artikelen wil houden.

### De seeder bij bouwblok 15
De seeder groeide van 22 naar 124 bronnen. Een platte lijst is dan niet meer te overzien, dus de array staat in groepen met een commentaarkop (`// --- VS: politiek ---`, `// --- Europa ---`, …). Binnen elke groep staan de bronnen van `left` naar `right`. Zo zie ik per regio meteen of een kant ontbreekt. Het land staat als commentaar achter de regel als dat niet uit de groep volgt.

### De seeder bij bouwblok 17
Elke regel heeft nu ook `'betrouwbaarheid' => 'high'` (of `mixed`, `low`, `null`), uit dezelfde MBFC-dataset als de oriëntatie. `Bron::insert()` maakt één SQL-insert van de hele array. Dan moeten alle rijen dezelfde keys hebben, dus ook de 9 bronnen zonder waarde krijgen expliciet `null`. Zie notitie 17.

## Een bestaande kolom wijzigen (bouwblok 17)
Een migratie die al gedraaid heeft, pas ik niet aan. Een andere machine heeft hem dan al uitgevoerd en ziet de wijziging nooit. Voor een wijziging maak ik een nieuwe migratie:
```php
Schema::table('artikelen', function (Blueprint $table) {
    $table->dateTime('publicatiedatum')->change();
});
```

`Schema::table` in plaats van `Schema::create`: de tabel bestaat al. `->change()` wijzigt de kolom in plaats van een nieuwe toe te voegen. In `down()` staat het omgekeerde, zodat `php artisan migrate:rollback` terug kan.

## Waarom ik het zo heb aangepakt
De casus vraagt om de bronkleur uit een kleine, zelf opgestelde tabel te halen in plaats van die automatisch te classificeren. Een seeder past daar precies bij: het is een vaste, herhaalbare lijst die ik zelf samenstel en die ik op elke machine met een commando opnieuw kan opbouwen, zonder dat ik data handmatig hoef over te zetten tussen mijn laptop en pc.
