#laravel #cheatsheet #medialens

Uitleg voor mezelf van wat ik gedaan heb bij bouwblok 3 van de MediaLens casus: artikelen groeperen tot gebeurtenissen met een eigen service-klasse en trefwoordmatching.

## Wat is een service-klasse
Een service-klasse is een gewone PHP-klasse waarin ik logica zet die niet in een command, controller of model thuishoort. Het command `artikelen:ophalen` haalt feeds op. Matching is een ander verantwoordelijkheid, dus die zet ik in `app/Services/GebeurtenisMatcher.php`.

Laravel heeft geen `make:service`. De map `app/Services` maak ik zelf aan. De namespace volgt uit de map (PSR-4 autoloading), ik hoef de klasse nergens te registreren.
```php
namespace App\Services;

use App\Models\Artikel;

class GebeurtenisMatcher
{
    public function koppel(Artikel $artikel): void
    {
        echo "Matcher aangeroepen voor: {$artikel->titel}\n";
    }
}
```

`koppel(Artikel $artikel)` is een type hint: PHP geeft een fout als ik er iets anders in stop. `: void` betekent dat de methode niets teruggeeft. Dit was de eerste versie. De huidige `koppel()` geeft een string terug, zie hieronder bij Koppelen.

In het command maak ik de matcher één keer aan, vóór de loop, en roep ik `koppel()` alleen aan na een écht nieuw artikel:
```php
use App\Services\GebeurtenisMatcher;

$matcher = new GebeurtenisMatcher();

$artikel = Artikel::create([ /* ... */ ]);
$matcher->koppel($artikel);
```

`Artikel::create()` geeft het opgeslagen model terug, inclusief `id`. Bestaande URL's worden door de duplicaatcheck overgeslagen, dus die gaan niet nog eens door de matcher.

> [!note] Tinker print bij een `: void` methode `= null`. Dat is de returnwaarde, geen fout. De `echo` erboven is de echte uitvoer.

## Trefwoorden uit tekst halen
Om twee artikelen te vergelijken heb ik per tekst een lijst losse woorden nodig.
```php
public function trefwoorden(string $titel): array
{
    $titel = html_entity_decode(strip_tags($titel), ENT_QUOTES | ENT_HTML5, 'UTF-8');
    $titel = mb_strtolower($titel);
    $woorden = preg_split('/[^\p{L}\p{N}]+/u', $titel, -1, PREG_SPLIT_NO_EMPTY);

    $woorden = array_filter($woorden, function ($woord) {
        return ! in_array($woord, $this->stopwoorden, true)
            && mb_strlen($woord) > 1;
    });

    return array_values(array_unique($woorden));
}
```

- `strip_tags` en `html_entity_decode` halen HTML en `&quot;` uit RSS-omschrijvingen.
- `mb_strtolower` maakt alles kleine letters, ook letters als é. Gewone `strtolower` kan die kapot maken.
- `preg_split('/[^\p{L}\p{N}]+/u', ...)` knipt op alles wat geen letter of cijfer is. De `u` is voor Unicode.
- `PREG_SPLIT_NO_EMPTY` laat lege stukjes weg.
- `array_unique` haalt dubbele woorden eruit, `array_values` zet de keys weer op 0, 1, 2.

`Trump's` wordt `trump` en `s`, omdat de apostrof als scheidingsteken telt. Die `s` filter ik later weg.

## Stopwoorden
Stopwoorden komen in bijna elke nieuwstekst voor en zeggen niks over welke gebeurtenis het is. Zonder filter zouden twee titels al matchen op `says`.
```php
private array $stopwoorden = [
    'a', 'an', 'and', 'as', 'at', 'be',
    'by', 'for', 'from', 'in', 'is',
    'it', 'its', 'of', 'on', 'or', 's',
    'says', 'the', 'this', 'to', 'with',
];
```

`private` betekent: alleen deze class mag de lijst zien. Dat is PHP, geen Laravel-specifiek iets.

`array_filter` houdt items waar de functie `true` van maakt. `in_array(..., true)` is strikte vergelijking. `mb_strlen($woord) > 1` gooit losse letters weg.

> [!warning] `array_diff` is iets anders dan `array_filter`. `array_diff($lijst, $andereLijst)` vergelijkt twee arrays. Het tweede argument mag geen functie zijn, dat geeft in PHP 8 een `TypeError`. Stopwoorden plus een lengtecheck horen in `array_filter`.

> [!note] Deze eigen lijst staat niet meer in de code. RAKE levert `en_US` (zie hieronder). De uitleg blijft staan vanwege `array_filter` vs `array_diff`.

## Overlap en drempel
```php
public function overlap(string $titelA, string $titelB): array
{
    return array_values(array_intersect(
        $this->trefwoorden($titelA),
        $this->trefwoorden($titelB)
    ));
}

public function zelfdeGebeurtenis(string $titelA, string $titelB): bool
{
    return count($this->overlap($titelA, $titelB)) >= $this->minimaleOverlap;
}
```

`array_intersect` geeft de woorden die in beide arrays staan. `count(...) >= $minimaleOverlap` maakt daar ja of nee van.

Op titels begon ik met drempel 2. Dat was te streng: 171 artikelen werden 140 losse gebeurtenissen, omdat koppen over hetzelfde feit te weinig woorden delen. Op omschrijvingen was 2 juist te los. Daarna 6, in Tinker, en 7 bij de eigen stopwoordenlijst. Na RAKE daalde de overlap (meer woorden vallen af). Drempel 7 koppelde te weinig, 5 te veel; in de code staat hij op 6 (`$minimaleOverlap`). `$maxDagen` ging van 3 naar 1. Of die groepen inhoudelijk kloppen, check ik nog in de browser en phpMyAdmin.

```php
private int $minimaleOverlap = 6;
private int $maxDagen = 1;
```

Die getallen staan in eigenschappen, niet als magisch getal in de `if`. Dan hoef ik later maar één plek te wijzigen.

## Matching op de omschrijving, niet de titel
De casus noemde overlap in de titel. In de praktijk geven bronnen dezelfde gebeurtenis een andere kop, dus te weinig matches. Ik vergelijk daarom `volledige_tekst` (de RSS-omschrijving). Het `onderwerp` van de gebeurtenis blijft de titel van het eerste artikel, alleen de matching verandert.

Eerste versie gaf na `strip_tags` tóch de ruwe kolom terug:
```php
private function vergelijkTekst(Artikel $artikel): string
{
    $tekst = trim(strip_tags((string) $artikel->volledige_tekst));

    return $tekst !== '' ? $artikel->volledige_tekst : $artikel->titel;
}
```

Tags telden dan mee. Een Guardian-digest van honderden woorden haalde drempel 7 met journalistiek-Engels (`said`, `tuesday`, `according`) tegen SCMP of NDTV. Trump/Iran, First Thing, liveblogs en Hongkong stonden in één groep.

Matching gebruikt nu alleen de **lede**: de eerste 40 woorden. De volle tekst blijft in de database, voor de AI in bouwblok 4 en 5.
```php
private function vergelijkTekst(Artikel $artikel): string
{
    $tekst = trim(strip_tags((string) $artikel->volledige_tekst));

    if ($tekst === '') {
        return $artikel->titel;
    }

    $woorden = preg_split('/\s+/', $tekst, -1, PREG_SPLIT_NO_EMPTY);

    return implode(' ', array_slice($woorden, 0, 40));
}
```

`array_slice($woorden, 0, 40)` is PHP: de eerste 40 items. `implode` plakt ze weer tot één zin. First Thing matcht dan nog op de openingszin over Trump/Iran, niet op de Israël-alinea verderop.

> [!note] Dit is een bewuste afwijking van de oorspronkelijke casusformulering. De kolom heet `volledige_tekst`, maar het blijft een RSS-samenvatting, geen gescrapete artikeltekst. De knip van 40 woorden geldt alleen voor matching.

> [!warning] Bestaande `gebeurtenis_id`s worden niet herberekend. Na een matcher-wijziging: `gebeurtenis_id` op NULL, `gebeurtenissen` legen, opnieuw `koppel()` op id-volgorde. Of `migrate:fresh --seed` plus `artikelen:ophalen`. Samenvattingen horen dan ook weg (foreign key naar `gebeurtenissen`).

## RAKE in plaats van de eigen stopwoordenlijst
Bouwblok 12 noemt RAKE als vervanging van die korte array. Package: `donatello-za/rake-php-plus` (v2). Dat is geen Laravel-package: geen service provider, geen `config`. Composer zet het in `vendor/`, daarna `use DonatelloZa\RakePlus\RakePlus`.

RAKE knipt de tekst bij stopwoorden en leestekens. Zo ontstaan zinsdelen, die een score krijgen. Twee manieren om het resultaat te vragen:

- `keywords()`: unieke losse woorden. Past bij `array_intersect` in `overlap()`.
- `get()`: zinsdelen, zoals `supreme court allowed`. Die matchen niet op `supreme court`, dus drempel 6 zou vrijwel nooit halen.

`en_US` omdat de RSS-feeds Engels zijn. De UI is Nederlands; `nl_NL` hoort hier niet.

```php
public function trefwoorden(string $titel): array
{
    $titel = html_entity_decode(strip_tags($titel), ENT_QUOTES | ENT_HTML5, 'UTF-8');

    if ($this->rake === null) {
        $this->rake = RakePlus::create($titel, 'en_US');

        return $this->rake->keywords();
    }

    return $this->rake->extract($titel)->keywords();
}
```

`strip_tags` blijft: RAKE haalt geen HTML weg. Geen eigen `mb_strtolower` meer, RAKE normaliseert zelf.

In Tinker, zin over SCOTUS: `keywords()` gaf o.a. `supreme`, `court`, `migrants`, `countries`. `third` viel af, dat zit in `en_US`. `get()` gaf `supreme court allowed` en `send migrants`.

Eerste meting op bestaande groepen (nog met drempel 7 in de code): twee stukken over dezelfde Senaatsrace deelden 9 woorden (`senate`, `ashley`, `hinson`, `josh`, `turek`, `medicaid`, …). Twee losse onderwerpen deelden 0. Daarna `migrate:fresh --seed` plus `artikelen:ophalen`: te weinig koppelingen bij 7, even 5, daarna 6 plus `$maxDagen = 1`. Steekproef of die groepen hetzelfde feit zijn, volgt nog.

`RakePlus::create()` laadt `en_US` elke keer. Zonder hergebruik werd `artikelen:ophalen` traag. De matcher houdt één `$rake`. Eerste tekst: `create()`. Daarna: `extract()`. Het command maakt de matcher één keer vóór de loop, dus die winst telt voor de hele run. Dat staat in de package-docs.

Dat was niet genoeg. `extract()` op dezelfde kandidaat bij artikel 50, 51, 52 is nog steeds RAKE. Daarom `$trefwoordCache`: sleutel = `artikelen.id`, waarde = de trefwoordenlijst.

```php
private array $trefwoordCache = [];

private function trefwoordenVan(Artikel $artikel): array
{
    $id = $artikel->id;

    if (! isset($this->trefwoordCache[$id])) {
        $this->trefwoordCache[$id] = $this->trefwoorden($this->vergelijkTekst($artikel));
    }

    return $this->trefwoordCache[$id];
}
```

`isset` is “staat dit id al in de array?”. Leermoment: `$rake` hergebruiken scheelt het laden van `en_US`. De cache scheelt het opnieuw knippen van dezelfde tekst. `trefwoorden()` blijft public voor Tinker met losse strings; die heeft geen artikel-id, dus geen cache. `koppel()` gebruikt alleen `trefwoordenVan()`.

## Koppelen: match of nieuwe gebeurtenis
`koppel()` gaf eerst niets terug (`void`) en printte zelf met `echo`. Dat hoort niet in een service: het command kan die regels niet tellen, en ze gaan buiten `$this->line()` om. De methode geeft nu een string terug. Drie paden, drie waarden:

- `overgeslagen`: het artikel had al een `gebeurtenis_id`
- `bestaand`: gekoppeld aan de gebeurtenis van een kandidaat
- `nieuw`: er was geen match, dus een nieuwe gebeurtenis

```php
public function koppel(Artikel $artikel): string
{
    if ($artikel->gebeurtenis_id !== null) {
        return 'overgeslagen';
    }

    $vanaf = Carbon::parse($artikel->publicatiedatum)->subDays($this->maxDagen)->toDateString();
    $tot = Carbon::parse($artikel->publicatiedatum)->addDays($this->maxDagen)->toDateString();

    $kandidaten = Artikel::where('id', '!=', $artikel->id)
        ->whereNotNull('gebeurtenis_id')
        ->whereBetween('publicatiedatum', [$vanaf, $tot])
        ->get();

    $woordenNieuw = $this->trefwoordenVan($artikel);

    foreach ($kandidaten as $kandidaat) {
        $woordenKandidaat = $this->trefwoordenVan($kandidaat);

        if (count(array_intersect($woordenNieuw, $woordenKandidaat)) >= $this->minimaleOverlap) {
            $artikel->update([
                'gebeurtenis_id' => $kandidaat->gebeurtenis_id,
            ]);
            return 'bestaand';
        }
    }

    $gebeurtenis = Gebeurtenis::create([
        'onderwerp' => $artikel->titel,
    ]);

    $artikel->update([
        'gebeurtenis_id' => $gebeurtenis->id,
    ]);

    return 'nieuw';
}
```

In Tinker print `koppel()` die string, niet meer `null`. Het command `artikelen:ophalen` telt `nieuw` en `bestaand` per bron. Zie notitie 2.

- Als het artikel al gekoppeld is, stop ik. Anders maakt een tweede aanroep een extra gebeurtenis.
- Ik vergelijk alleen met artikelen die al een `gebeurtenis_id` hebben. Anders is er niks om over te nemen. Het eerste artikel in een groep maakt de gebeurtenis, de rest koppelt daaraan.
- `whereDate('publicatiedatum', $zelfdeDatum)` gebruikt nu alleen de exacte publicatiedatum van het artikel. De matcher is bewust strikter: een volgende dag is geen continue gebeurtenis, maar een nieuwe kans op een ander onderwerp.
- Geen match: nieuwe rij in `gebeurtenissen`, daarna `gebeurtenis_id` op het artikel zetten.

`Gebeurtenis` heeft `$fillable = ['onderwerp']` nodig, anders geeft `create()` weer een `MassAssignmentException`. Dat had ik bij Artikel in bouwblok 2 al geleerd.

> [!warning] Eloquent-kolommen heten zoals in mijn migratie. `$artikel->title` bestaat niet, de kolom is `titel`. Eloquent geeft dan `null` in plaats van een duidelijke fout. Daarna crasht `zelfdeGebeurtenis(string $titelA, ...)` met `must be of type string, null given`. Dat lijkt een fout in de matcher, maar het is een verkeerde kolomnaam.

> [!warning] `where('gebeurtenis_id', null)` is "IS NULL". `whereNotNull('gebeurtenis_id')` is het omgekeerde. Toen ik per ongeluk op NULL filterde, kopieerde een "match" een lege id over en werd er nooit een gebeurtenis aangemaakt. In Tinker bleef `gebeurtenis_id` dan `null`.

## Tijdvenster
Twee artikelen over dezelfde woorden met drie weken ertussen zijn waarschijnlijk niet dezelfde gebeurtenis. De matcher is nu same-day-only: de vergelijking gebruikt alleen artikelen met dezelfde publicatiedatum (`$maxDagen = 0`). Een artikel van 8 okt matcht alleen andere artikelen van 8 okt. Een volgende dag wordt als nieuwe kans gezien, ook als de woorden sterk op elkaar lijken. Een smaller venster betekent minder kandidaten, dus sneller `koppel()`, en voorkomt dat de groep onbedoeld doorloopt naar een ander nieuwsitem op een nieuwe dag.

Bestaande koppelingen worden niet herberekend als ik de drempel of het venster aanpas. Dan eerst (samenvattingen vóór gebeurtenissen, vanwege de foreign key):
```sql
DELETE FROM samenvattingen;
UPDATE artikelen SET gebeurtenis_id = NULL;
DELETE FROM gebeurtenissen;
```
Daarna in Tinker alle artikelen opnieuw koppelen, op id-volgorde, want het eerste artikel in een groep opent de gebeurtenis:
```php
$m = new App\Services\GebeurtenisMatcher();
App\Models\Artikel::orderBy('id')->get()->each(function ($artikel) use ($m) {
    $m->koppel($artikel);
});
```

## Wat ik verkeerd zag in de feeds
Trefwoordmatching is maar zo goed als de tekst die ik erin stop.

Drudge Report zette in `description` pagina-HTML: Patreon, Daily Mail-kolom, feedpress-GIF. Elk item deelde die boilerplate, dus de matcher groepeerde ongerelateerde koppen (oermens vs een arts over sterven) op dezelfde `gebeurtenis_id`. Drempel 10 hielp daar niet tegen, de schil was langer dan 10 woorden.

The Nation had hetzelfde probleem: layout-HTML plus "appeared first on The Nation".

`strip_tags` haalt tags weg, niet de herhaalde reclamezin daaronder.

Die bronnen heb ik uit de seeder gehaald. Daarvoor in de plaats: The Daily Signal (`right`) en The Washington Post (`left-center`). Bij beide heb ik gecontroleerd dat `description` per artikel een echte alinea of zin is, en dat de publicatiedatums recent zijn.

> [!tip] Bij een nieuwe feed altijd een paar `volledige_tekst`-waarden openen, niet alleen de titel of status 200. HTML-blobs herken ik doordat meerdere items dezelfde Patreon-, "appeared first"-, "Get our … podcast"-, "Listen to the podcast"- of navigatietekst hebben.

The Nation (`left`) is later teruggezet, zodat het spectrum weer een echte `left` heeft. Eerder was de `description` layout-HTML. Bij het ophalen gaan tags en `Continue reading...` er nu af (notitie 2). Toch na `artikelen:ophalen` een paar Nation-rijen in phpMyAdmin openen.

Sinds bouwblok 15 zijn er 124 bronnen en heeft elk label er meerdere. De actuele lijst staat in `BRONNEN.md` en in `BronSeeder`, de testaanpak in notitie 15.

> [!warning] Meer bronnen betekent meer kandidaten per dag voor `koppel()`. Ketting-matching (hieronder) wordt daardoor eerder zichtbaar. Na de eerste run met alle bronnen de groepen opnieuw steekproefsgewijs bekijken.

## Ketting-matching
De matcher koppelt aan de eerste kandidaat die de drempel haalt, niet aan de beste, en niet aan "de hele groep gaat over hetzelfde". Artikel B matcht A, artikel C matcht B, en C komt in dezelfde gebeurtenis terecht zonder dat C en A over hetzelfde gaan.

Voorbeeld dat ik zelf zag, vóór de knip van 40 woorden: NYT/CBS/LA Times over Trump die Iran/LA noemt hoorden bij elkaar. Guardian First Thing (een ochtendoverzicht) begon met dat feit en sleepte daarna de hele digest in de groep. NDTV over Britse diplomaten deelde 7 woorden met de Israël-alinea in die digest. SCMP over Hongkong deelde journalistiek-Engels met dezelfde zak.

De lede-knip maakt die tweede sprong veel moeilijker. Eerste-match-wint blijft: SCOTUS plus student loans via `trump` kan nog. Dat is geen bug in de query, het is de beperking van deze methode. Embeddings zouden betekenis vangen, maar hoorden niet bij dit bouwblok.

Na die knip zag ik het opnieuw bij Guardian Australia in de World-feed. Tussen standfirst en alinea zitten twee `<li>`-promo's: `Get our … email … free app or daily news podcast` en soms `Listen to the podcast` plus een wisselende serietitel. Na tag-strip landt dat in de eerste 40 woorden. Acht trefwoorden die niet in de oude `$stopwoorden` stonden (`get`, `our`, `email`, `free`, `app`, `daily`, `news`, `podcast`), toen drempel 7. Kolenmijn-uitspraak, immigratiebelofte en moordzaken werden één gebeurtenis. ABC over dezelfde NSW-kolenmijn hoorde inhoudelijk bij het eerste Guardian-stuk; de rest liftte mee via de promo. `en_US` knipt nu woorden als `get` en `our` weg, maar `email`/`podcast` kunnen nog overlap geven. De echte fix blijft de `<li>`-blokken bij het ophalen, vóór tags naar spaties (notitie 2). Een tekstfilter ná tag-strip op `email,?` miste de zin, omdat `</a>,` een spatie werd (`email ,`). Bestaande rijen: `volledige_tekst` bijwerken, daarna resetten en opnieuw koppelen zoals hierboven.

## Waarom ik het zo heb aangepakt
De casus noemde embeddings, named entities, event-detectie en keyword-extractie. Keyword-extractie is niet de sterkste methode, maar wel uitlegbaar in Tinker en phpMyAdmin. Eerst zonder extra package: eigen stopwoordenlijst. RAKE (`rake-php-plus`) is diezelfde aanpak, met een echte Engelse stopwoordenlijst en zinsdeel-scores. `koppel()` (nieuwe gebeurtenis vs bestaande, `gebeurtenis_id`, tijdvenster) blijft hetzelfde. Als ik later embeddings in `koppel()` stop, blijft de rest van de app hetzelfde.

## Beperkingen om te onthouden
- Matching op de eerste 40 woorden van de RSS-omschrijving, niet op titel, en nog steeds geen volledige artikeltekst.
- Drempel 6, 40 woorden en `$maxDagen = 1` zijn knoppen op deze set, geen wet. 6 volgde op te weinig koppelingen bij 7 en te veel bij 5 na RAKE; of de groepen inhoudelijk kloppen, is een aparte check.
- `keywords()` telt losse woorden, geen RAKE-zinsdelen.
- Eerste match wint, ketting-matching blijft mogelijk, vooral via korte gedeelde namen (`trump`).
- Vuile `description` maakt de hele matcher onbruikbaar voor die bron. De WordPress-footer van The Nation zat bij korte items in de eerste 40 woorden. De Guardian-promo's (`Get our …` en `Listen to the podcast …`) deden hetzelfde bij AU-items (`get`/`email`/`podcast`, 8 woorden, toen drempel 7). Die `<li>`-blokken haal ik bij het ophalen weg, zie notitie 2, niet hier in de matcher.
- Na een wijziging in de matcher moet ik `gebeurtenis_id` resetten en opnieuw koppelen. `create()` per aanroep maakt `artikelen:ophalen` traag; houd één `$rake` en gebruik `extract()`. Zelfde kandidaat bij elk nieuw artikel: `$trefwoordCache` via `trefwoordenVan()`.
